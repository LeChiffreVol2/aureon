This reference is distinct from the [v0.19.0 wrapper](https://github.com/vllm-project/vllm/blob/v0.19.0/vllm/model_executor/models/terratorch.py).

Referencing field names or documenting compatibility is not presented here as proof that the whole upstream implementation was copied. The [vLLM 0.19.0 license](https://github.com/vllm-project/vllm/blob/v0.19.0/LICENSE) is Apache-2.0.

The inspected repository roots at the two TerraTorch commits, the KAO-TerraMind GitHub commit, and the resolved vLLM commit contain LICENSE but no root NOTICE file. Therefore this candidate's NOTICE is an attribution compilation, not a claimed copy of a nonexistent upstream root NOTICE. File-level notices still matter. This check does not certify every transitive dependency or nested package.

## Dependencies installed by the user

The candidate must not bundle runtime wheels, shared libraries, CUDA components, or environment directories. NumPy and optional geospatial/neural runtimes retain their own licenses. The reviewed runtime evidence used TerraTorch 1.2.13 and vLLM 0.19.0 under Apache-2.0, and PyTorch [2.10.0](https://github.com/pytorch/pytorch/blob/v2.10.0/LICENSE)/[2.11.0](https://github.com/pytorch/pytorch/blob/v2.11.0/LICENSE) under BSD three-clause terms; the proposed package's permitted version ranges are a separate packaging decision. Importing a package does not mean its full binary distribution is embedded in the AUREON wheel. A future container or bundled runtime needs a separate exact dependency/binary notice review.

The generation adapter calls separately installed TerraTorch 1.2.13 TerraMind model/tokenizer implementations and their NumPy/PyTorch, diffusion and transformer dependencies. The candidate carries a 37-file upstream hash inventory for exact local compatibility, not a vendored upstream implementation or dependency SBOM. Pinned TerraMind base and S1GRD tokenizer weights remain external; listing identity does not grant redistribution rights. AUREON-owned attribution now identifies Norvique Company; third-party attribution remains separate. The pinned asset URLs/checksums are in [ASSETS.md](../ASSETS.md).
