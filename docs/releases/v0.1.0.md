# AUREON v0.1.0 — public alpha

The library release provides self-directed local KAO-TerraMind and TerraMind
workflows: exact installation, pinned asset discovery, user-owned Sentinel-2
preparation, Python/CLI inference and authenticated HTTP artifact delivery.
It does not launch a hosted service or include model weights or imagery.

## Interfaces

- `aureon-engine assets`: official pinned sources and checksums, without downloads.
- `aureon prepare-vllm`: create your own local B bundle from the pinned checkpoint.
- `aureon-prepare scene` and `generation`: user-owned scene and all-valid224 crop preparation.
- `aureon-engine run` / `generate`, and `aureon.api`: explicit offline execution.
- `aureon-service` / `aureon-service-client`: authenticated local submission and verified downloads.

## Verification and scope

Both locked Python3.12 Linux profiles passed fresh offline installation and
`pip check`, matching153 hashed wheel payloads per environment. Source/API CPU
contracts passed68 tests. Installed layout and public-alpha workflow tests passed
22 checks with two optional external-bundle checks skipped. The portable kit was
verified after relocation. These CPU checks establish no model-performance claim.

The final wheel then passed one guarded-v3 KAO-TerraMind B512 and one TerraMind224
real HTTP job on RTX3070/WSL, with retained FP32 parity, saved COG/provenance checks,
idempotent replay/once-only usage and CUDA0/0 shutdown. See the
[support matrix](../MODEL-SUPPORT.md) for the precise model/hardware boundaries.
No comparative benchmark was run for publication, and no new speed claim is made.
